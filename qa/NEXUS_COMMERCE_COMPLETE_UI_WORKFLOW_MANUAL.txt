  - 404 handler for unknown /api/*; central errorHandler.

TOKEN MODEL
  - Access token (JWT, short-lived) in localStorage `accessToken`; refresh token in
    localStorage `refreshToken`; refresh token row is a Session in DB (isActive,

    (storefront api.ts, retailer api.ts, dev api.ts) auto-refresh on 401 once, then
    drop tokens and redirect to /login (storefront/retailer) / route.replace login. [OK]
  - Dashboard SSO: URLs like `/dashboard#token=<accessToken>` are consumed by
    `captureTokenFromUrl()` (both dashboards) which stores token and strips hash. [OK]
  - Branding: embeddable mini-app. Retailer store name: "Lyn-nyx Stores". Primary

RESPONSE CONTRACT

  - errors: { success:false, error:'<msg>' } with 400/401/403/404/409/502/503.

2. AUTHENTICATION WORKFLOWS (STOREFRONT) 
================================================================================

lib/auth.tsx AuthProvider:
  - loadUser on mount: if accessToken → GET /auth/me → setUser. 401 clears tokens.
    Network errors retry up to 4x at 5/15/25/35s (Render cold start guard). [OK]

completeSession(res):
  - Stores access+refresh tokens; branch by role:
    * RETAILER: GET /stores/mine. Has store → hard redirect
      RETAILER_DASHBOARD_URL + /dashboard#token=<accessToken>.
      No store → router.push('/create-store'). [OK]
    * DEVELOPER/SUPER_DEVELOPER → dev URL + /dashboard#token=. [OK]
    * CUSTOMER → router.push('/account'). [OK]

EMAIL + PASSWORD LOGIN (/login):
  - POST /api/auth/login. Errors surfaced: invalid creds 401, suspended 403,
    unverified → 403 code EMAIL_NOT_VERIFIED → inline "verify your email" box with
    `Resend verification email` (POST /auth/resend-verification). [OK]
  - Login success → completeSession (role-based redirect above). [OK]

GOOGLE LOGIN (/login, /register):
  - window.location = API_BASE + /api/auth/google (GET, redirects to Google).
    API google/callback → creates/links user → redirects
    ${AUTH_REDIRECT_URL}/auth/callback?accessToken=...&refreshToken=...
    Storefront /auth/callback parses query token(s), calls completeSession. [OK]
    Denied/no-email/account-suspended → {origin}?error=... (storefront root). [WARNING]
    googleId migration + unique index present; first-time CUSTOMER profile created. [OK]

MAGIC LINK (/login → "send link" + /auth/magic-link):
  - POST /auth/magic-link { email } → validates email, config check (503 if unset),
    creates 15-min token, emails link `${AUTH_REDIRECT_URL}/auth/magic-link?token=..&email=..`.
    UI shows "If that email is registered, a sign-in link has been sent." [OK]
  - /auth/magic-link page: reads token+email, POST /auth/magic-link/verify.
    Auto-creates account (CUSTOMER, passwordHash null, emailVerified true) if missing;
    marks verified if existing; suspended users blocked 403. Returns tokens → completeSession. [OK]

REGISTER (/register):
  - Fields firstName, lastName, email, password, confirm, role (Customer|Retailer).
    Client rules: passwords equal, password >= 6. [OK]
  - POST /auth/register. Server: email format + TLD + disposable-blocklist checks,
    password >= 6, duplicate 409, role whitelist (CUSTOMER/RETAILER/DEVELOPER→ else CUSTOMER).
    Creates auth + role profile + always a Customer profile. [OK]
  - If email configured: creates 24h verify token, sends email, responds
    requiresEmailVerification → storefront pushes /auth/check-email?email=.
    If NOT configured: returns tokens directly (register succeeds logged-in). [OK]
  - Retailer registration pre-creates a Retailer row (storeName "<First>'s Store",
    storeSlug "<first>-<base36 timestamp>") → completeSession routes to /create-store. [OK]
  - /auth/check-email: shows address + "Resend" (POST /auth/resend-verification),
    "Back to sign in". [OK]
  - /auth/verify-email: POST /auth/verify-email (token+email). Invalid/expired 401;
    already-verified → confirm message; success → "You can now sign in". Stays on
    storefront (does not auto-login). [OK]

LOGOUT: clear localStorage tokens, setUser null, push '/'. Does NOT call
  /auth/logout (session row stays active until expiry). [WARNING] server session
  not revoked on logout.

CHECKOUT GATE: /checkout redirects to /login when no user (authLoading first). [OK]

4. CART WORKFLOW
================================================================================
Server (routes/cart.ts, requireStore):
  - POST /cart/dedup: maintenance-ish; de-dupes cart_items by (cartId,productId,
    variant null). Public. [OK]
  - GET /cart: optionalAuth. Identifies cart by customerId (user) OR sessionId header;
    neither → empty payload. Returns subtotal+total (total = subtotal - couponDiscount).
    taxAmount/shippingCost always 0 (POD model). [OK]
  - POST /cart/add: authenticate + store. Requires cart per user. Merge quantity if
    same (product, variant). vId null for '' legacy. Returns full cart. [OK]
  - PUT /cart/item/:id {quantity}, DELETE /cart/item/:id: optionalAuth, direct row ops
    (owner-scoping of item id not enforced). [WARNING] item-id ops not scoped to caller.
  - POST /cart/coupon {code}: validates active, unexpired, uses<maxUses; recomputes
    discount (percentage of subtotal or fixed); saves couponCode/couponDiscount on cart;
    returns display string. [WARNING] maxUses not incremented here (increments likely
    missing across flows), and minPurchase not enforced though field exists.

UI /cart (page.tsx):
  - Loads GET /cart. Empty state → Continue Shopping. Non-empty: line items with

6. PAYMENTS (ONLINE) — PESAPAL / FLUTTERWAVE
================================================================================
Providers (payments/index.ts): getPaymentProvider maps mtn_momo, airtel_money,
  pesapal → PesapalProvider; flutterwave → FlutterwaveProvider. Both resolve secrets

  - Auth RequestToken (consumer key/secret, base from PESAPAL_BASE_URL setting or
    https://pay.pesapal.com prod). RegisterIPNURL (ipn_notification_type GET). [OK]
  - charge(): SubmitOrderRequest with id=reference, currency UGX, amount, callback_url,
    notification_id, billing (email/phone/UG). Returns order_tracking_id /
    merchant_reference → PENDING. [OK]
  - verify(): GetTransactionStatus; payment_status_description COMPLETED → PAID. [OK]
  - refund(): returns "must be processed in Pesapal merchant dashboard" (unsupported
    programmatically). [OK]

FLUTTERWAVE (payments/flutterwave.ts):
  - charge with network+phone → mobile_money_uganda charge (tx_ref=reference).
    Without → /v3/payments redirect flow. [OK]
  - verify(): /v3/transactions/:id/verify → success+successful→PAID. [OK]
  - refund(): POST /transactions/:id/refund. [OK]

API surface (routes/payments.ts):
  - GET /callback/pesapal (NO auth): verifyAndMark → redirect
    ${STOREFRONT_URL}/checkout?status=callback&order=<ref>. [OK]
  - GET|POST /ipn/pesapal (no auth): on pesapal_notification_type=CHANGE →
    verifyAndMark; responds OK. [OK]
  - POST /callback (flutterwave style): on status successful/completed → markPaid
    by transaction_id||tx_ref. [OK]
  - POST /charge (auth + requireStore): order scoped by storeId header; provider by
    method (pesapal|mtn_momo|airtel_money → pesapal; flutterwave); constructs
    callback/ipn URLs from req host; creates Payment row (PENDING) on success. [OK]
    [WARNING] No customer-ownership check: any authenticated user knowing an order id
    in that store can initiate a charge against it.
  - markPaid: payment PENDING→PAID, order paymentStatus PAID + status PROCESSING. [OK]
  - POST /verify (auth+requireStore): manual verify + mark. [OK]

SUBSCRIPTION payments live under /api/subscriptions (see §14). Flutterwave webhook
  handles SUB- tx_refs there; verif-hash secret validated; non-SUB tx_refs update
  order payments. [OK]
