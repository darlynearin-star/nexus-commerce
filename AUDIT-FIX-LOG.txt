FUNCTIONAL / API ISSUES
==================================================================

[T1] - H1 RETAILER STORE TOGGLE = PERMANENT 403
  WHERE:  packages/api/src/routes/stores.ts:162 (POST /stores/:id/toggle
          requires Permission.MANAGE_SYSTEM)
          packages/shared/src/types.ts:49-60 (RETAILER role lacks it)
          packages/retailer-dashboard/src/app/settings/page.tsx:54
  WHY:    The retailer's "Deactivate/Activate store" button always fails
          with 403. Only SYSTEM managers can toggle.
  FIX:    Allow the store OWNER (or dev/super-dev) to toggle their own
          store; keep the SYSTEM permission for admins.
  STATUS: DONE (owner + staff can toggle; typecheck passed)

[T2] - H2 DRAFT/ARCHIVED PRODUCTS LEAKED TO ANY LOGGED-IN USER
  WHERE:  packages/api/src/routes/products.ts:82-86
  WHY:    Anonymous callers get PUBLIC only, but any authenticated caller
          who omits ?status= gets ALL statuses (incl. DRAFT/ARCHIVED).
          No ownership check, so a customer can read drafts with prices.
  FIX:    Force PUBLIC for any caller who is not the store owner or a
          staff role, no matter what ?status= says.
  STATUS: DONE (typecheck passed)

[T3] - H4 GET /subscriptions FLIPS TRIAL -> SUSPENDED ON READ
  WHERE:  packages/api/src/routes/subscriptions.ts:24-27
          packages/api/src/middleware/subscription-check.ts:28-31
  WHY:    Just READING the subscription state permanently kills the
          subscription. This breaks the 3-day grace period and the
          enforcer never gets a chance to suspend the store properly.
  FIX:    Never mutate state on a GET. Return the state as-is; let the
          enforcer be the only writer that suspends.
  STATUS: DONE (typecheck passed)

[T4] - H5 CUSTOMERS BLOCKED READING ORDERS ON LAPSED STORES
  WHERE:  packages/api/src/middleware/subscription-check.ts:10-21
  WHY:    requireActiveSubscription only looks at the store's owner
          subscription, so a CUSTOMER reading their own order history on
          a lapsed store gets a 403 "Store is suspended" error.
  FIX:    Only gate the store owner (and block non-owner writes). Allow
          customers to READ their own orders.
  STATUS: DONE (typecheck passed)

[T5] - H6 CANCELLED SUBSCRIPTION IS A DEAD END IN THE UI
  WHERE:  packages/retailer-dashboard/src/app/account/subscription/page.tsx
  WHY:    No action button is rendered for CANCELLED status, so the
          retailer cannot resubscribe without admin help.
  FIX:    Render a "Resubscribe" button for CANCELLED too.
  STATUS: DONE (typecheck passed, api + retailer)

[T6] - H3 COUPONS READABLE WITHOUT AUTH
  WHERE:  packages/api/src/routes/coupons.ts:7
  WHY:    GET /coupons has no authenticate() - full coupon rows incl.
          codes and business rules are readable by anyone.
  FIX:    Add authenticate() to the coupons router.
  STATUS: DONE (GET now owner-only; typecheck passed)

[T7] - M10 UNLOCK LEAVES GRACE FLAGS SET
  WHERE:  packages/api/src/routes/subscriptions.ts (unlock endpoint)
  WHY:    Admin unlock reactivates the sub but leaves
          graceNotifiedAt/suspendedAt set, which can confuse later logic.
  FIX:    Clear graceNotifiedAt/suspendedAt when unlocking.
  STATUS: DONE (typecheck passed)
